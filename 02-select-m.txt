# Layer 02 (flavor 2: drivers modularized) -- architecture-independent driver
# layer, mutually exclusive with select-y.
#
# Semantics: every board driver (including the SoC-specific IP moved in from
# layer 01) is =m, shrinking the kernel image; the module
# set is delivered by the initramfs/rootfs. Two exception classes stay built
# in:
#   * boot-critical path: the serial console (cannot produce output before
#     insmod can run);
#   * bool switches (cannot be m; identical in both flavors) and symbols the
#     tree force-sets (AMBA_PL08X, POWER_RESET_SYSCON and RESET_HISI are bool;
#     PINCTRL_SINGLE rejects a user value of m and snaps back to y -- measured,
#     force mechanism unidentified). For these four, "off" is what does not
#     exist, so both flavors carry them built in.
# Root storage is NOT an exception here: MMC_DW and its variants are =m like
# every other driver; the convenience layer (03) raises the root-storage
# devices back to =y so mounting root never depends on the module set.
# Skeleton parents: bool gates are written =y (cannot be m). Tristate parents
# carried by the distribution baseline (=y) are not repeated.
# Side effect: tristate lines that depend on an m-parent land as =m instead of
# =y -- that is the point of this flavor. The verification treats "landed as m
# or y" as landed and only "absent/not-set" as a failure; bools are checked
# strictly.
#
# Boot-critical path, built in:
CONFIG_SERIAL_AMBA_PL011=y
CONFIG_SERIAL_AMBA_PL011_CONSOLE=y
